### Assignment 2 - Better diagnostics

**Deadline:** Tuesday December 8st, 23:59

**Group deliverable:** 
1. 10 broken programs that you believe are meaningful for error reporting;
2. a before-and-after comparison of the error reporting (the "before" is the class compiler, the "after" is your deliverable for this assignment);
3. a local, runnable project with your modified files that runs on the examples of point 1 and shows the errors of point 2.
4. a short (1-page) description of your solution (what files you changed and how) and the lessons learned.

Errors today are a string and a span, printed as one line.
The goal of the project is to build what a modern compiler does:

- A `Diagnostic` type: severity, primary span with a message, secondary spans
  ("`x` was declared here as `int`"), and an optional suggestion
- Rustc-style rendering: source line, carets under the span, line numbers,
  colour when the output is a terminal
- **Error recovery in the parser** so that more than one error is reported per
  run. This is the substantial part: it means synchronisation points, and an
  `ExpressionKind::Error` node so later passes can keep walking a broken tree.
- Multi-error output from the typechecker, which today stops at the first failure
